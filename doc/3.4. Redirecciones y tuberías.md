# Redirecciones y tuberías (pipes) en Bash / POSIX

Este documento explica **de forma completa y rigurosa** las redirecciones y la **tubería (`|`)**, incluyendo qué existe realmente, para qué sirve cada operador y cómo combinarlos correctamente en scripts.

Orientado a **ASIR / SMR / administración de sistemas**.

---

## 1. Descriptores estándar (fundamento)

En Unix todos los procesos trabajan con **descriptores de fichero**:

| Descriptor | Número | Significado |
|-----------|--------|-------------|
| STDIN | 0 | Entrada estándar |
| STDOUT | 1 | Salida estándar |
| STDERR | 2 | Salida de error |

Las redirecciones actúan **sobre estos descriptores**, no “sobre comandos”.

---

## 2. Referencias a descriptores: `&0`, `&1`, `&2`

Antes de ver redirecciones combinadas es imprescindible entender **qué significa `&1`** (y similares).

### Qué es `&1`

- `1` representa el descriptor **STDOUT**
- `&` indica que **no es un fichero**, sino **una referencia a un descriptor**

👉 **`&1` significa: _el mismo destino que el descriptor 1 (STDOUT)_**.

Por sí solo, `&1` **no hace nada**.  
Solo tiene sentido **dentro de una redirección**.

### Ejemplo clave

```bash
2>&1
```

Se lee como:

> “Redirige STDERR (2) al mismo destino que STDOUT (1)”

### Por qué el `&` es obligatorio

```bash
2>1     # STDERR se redirige a un fichero llamado '1'
2>&1    # STDERR se redirige a STDOUT
```

El `&` marca la diferencia entre **descriptor** y **nombre de fichero**.

### Otras referencias posibles

| Referencia | Descriptor |
|-----------|------------|
| `&0` | STDIN |
| `&1` | STDOUT |
| `&2` | STDERR |

Ejemplo válido (poco habitual):

```bash
1>&2   # envía STDOUT a STDERR
```

## 3. Redirecciones de entrada

### `<` — Fichero → STDIN (POSIX)

```bash
comando < fichero.txt
```

- Redirige un fichero a la entrada estándar
- POSIX
- Muy eficiente

Ejemplo:
```bash
wc -l < fichero.txt
```

---

### `<<` — Here-document (bloque → STDIN) (POSIX)

```bash
comando << EOF
línea 1
línea 2
EOF
```

- Bloque de texto dentro del script
- Puede expandir variables
- POSIX

Ejemplo:
```bash
grep error << EOF
ok
error crítico
EOF
```

---

### `<<<` — Here-string (cadena → STDIN) (**Bash**)

```bash
comando <<< "texto"
```

- Pasa una **cadena** como entrada
- No POSIX (Bash, zsh, ksh)
- Más eficiente que `echo | comando`

Ejemplo:
```bash
rev <<< "radar"
```

---

## 4. Redirecciones de salida

### `>` — STDOUT → fichero (sobrescribe) (POSIX)

```bash
comando > salida.txt
```

---

### `>>` — STDOUT → fichero (añade) (POSIX)

```bash
comando >> salida.txt
```

---

## 5. Redirecciones de error

### `2>` — STDERR → fichero (sobrescribe) (POSIX)

```bash
comando 2> errores.txt
```

Ejemplo:
```bash
ls /noexiste 2> error.log
```

---

### `2>>` — STDERR → fichero (añade) (POSIX)

```bash
comando 2>> errores.txt
```

---

### `2<` — STDERR como entrada (existente pero no práctico)

```bash
comando 2< fichero
```

- Sintácticamente válido
- Prácticamente inútil: los comandos **no leen de STDERR**
- No se usa en scripts reales

---

## 6. La tubería (`|`) — Pipe (POSIX)

### Qué es una pipe

La tubería conecta:

> **STDOUT de un comando → STDIN del siguiente**

```bash
comando1 | comando2
```

---

### Ejemplo básico

```bash
ls | wc -l
```

---

### Pipes encadenadas

```bash
ps aux | grep root | wc -l
```

Cada `|` crea:
- un pipe
- procesos en paralelo

---

## 7. Pipes y errores

Por defecto:
- `|` **solo conecta STDOUT**
- STDERR **no pasa por la pipe**

```bash
comando1 | comando2
```

Para incluir errores:

```bash
comando1 2>&1 | comando2
```

Aquí `2>&1` redirige primero los errores al mismo destino que STDOUT, y después la pipe los conecta.

---

## 8. Redirecciones combinadas

### Guardar salida y errores por separado

```bash
comando > salida.txt 2> errores.txt
```

---

### Guardar todo en un solo fichero

```bash
comando > todo.txt 2>&1
```

⚠️ **El orden importa**:

```bash
comando 2>&1 > todo.txt   # resultado distinto
```

Las redirecciones se procesan **de izquierda a derecha**.

---

## 9. Tabla resumen definitiva

| Operador | Descriptor | Función | POSIX |
|--------|------------|--------|-------|
| `<` | 0 | Fichero → STDIN | ✔ |
| `<<` | 0 | Bloque → STDIN | ✔ |
| `<<<` | 0 | Cadena → STDIN | ❌ |
| `>` | 1 | STDOUT → fichero | ✔ |
| `>>` | 1 | STDOUT → fichero (append) | ✔ |
| `2>` | 2 | STDERR → fichero | ✔ |
| `2>>` | 2 | STDERR → fichero (append) | ✔ |
| `2<` | 2 | STDERR como entrada (no práctico) | ✔ |
| `\|` | 1 → 0 | STDOUT → STDIN | ✔ |
| `&1` | ref | Referencia a STDOUT | ✔ |

---

## 10. Errores típicos (examinables)

❌ Pensar que `&1` crea un fichero  
❌ Confundir `>` con `|`  
❌ Creer que la pipe incluye errores por defecto  
❌ Usar `<<<` en scripts `/bin/sh`  
❌ No entender el orden de `2>&1`  

---

## 11. Regla de oro

> `<` / `<<` / `<<<` → entrada  
> `>` / `>>` → salida  
> `2>` / `2>>` → errores  
> `&1` → referencia a STDOUT  
> `|` → conectar comandos

---

## Conclusión

- Las **redirecciones** conectan procesos con ficheros o cadenas
- `&1` permite **unificar destinos**
- La **pipe** conecta procesos entre sí
- Dominar estos conceptos es **clave en scripting profesional**
